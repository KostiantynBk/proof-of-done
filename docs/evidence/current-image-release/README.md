# Current-image bounded verification — separate from historical audit

On 8 November 2026, the team ran one reviewed, bounded real-VM integration suite against the then-current sandbox image `sha256:e57243f7dac1425ad9fe0c844e03f74a0f5f15b253e177e0ccd47fcb10850697`. The historical recorded audit used image `sha256:0c6edc5075e36402d70571708f10d9c4d7558e7fadba82ac2f4144626d9144b9`: these are different images, and no layer equivalence or re-execution of the audit is claimed. The historical run's 65 sandbox receipts and four exports are [preserved separately](../55cef2ea9d72408c9d96e4e1f89811b2/README.md).

The existing integration suite was adapted to select the exact current image without building or retagging it. The plugin adds tracking and checks actual created container identities/configuration; workloads, assertions and cgroup counters are not mocked. The captured invocation reported **2 passed**, with **10 runsc sandbox containers and one separate runc bridge-network positive control**, all using the current image. Before service restart, the saved inventory recorded all 11 IDs absent, no labeled/tagged containers, no workroot entries and no suite processes. Tested scenarios included normal/follow-up execution, nested restrictive-permission cleanup, network-blocked vs reachable-IP control, fake-canary telemetry, wall timeout, memory and PID caps. Two PID scenarios observed `pids.max=128`, current reaching 128 and max-event counter 0→1, with runsc error/exit 2—not graceful guest refusal. This is bounded evidence, not a general isolation guarantee; telemetry is best effort.

`current-image-suite.log`, `post-suite-inventory.json`, `results-*`, `current_image_plugin.py` and `run_current_image_suite.sh` are **exact copied evidence bytes**, not fresh proof or instructions to run. Scripts are included for review and are potentially disruptive operational code: do not execute them as part of checking this pack. The suite includes a fake canary, not a real credential. `SHA256SUMS` lists their byte hashes; `sha256sum -c SHA256SUMS` reads files without running scripts or target code. Hashes support consistency, not authenticated provenance. Exact matches against the two then-current keys and a limited user-path check found no matches; this is not a comprehensive secret audit. The evidence was reviewed independently using saved data; see project release notes for scope and limitations.
